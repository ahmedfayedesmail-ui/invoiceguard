## Test change disclosed: A4a (test/credit-note-hold-guards.test.js), approved by Main 13:50
Why: CI run 46140997242 failed once on A4a (round 1: replacement stamped 11:40:59.454, hold first_seen 11:40:59.449). Both stamps are taken before their transaction waits for the SQLite write lock, so wall-clock order is not commit order. The DB trigger forbids a replacement inserted after the hold committed, so the failure was a stamp artifact. Before: assert issued_at <= hold first_seen. After: assert the replacement's event rowid (same transaction as the row) is lower than the first credit_note_hold event rowid (commit order). The new assertion cannot false-fail on stamps and still fails on a real ordering violation: reversing the comparison makes A4a fail locally (checked), so replacements do occur in those rounds and the check is live. Passed 4/4 locally after the change.
