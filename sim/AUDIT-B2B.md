## After the B2B fix: 8 left (audit-b2b-8-after-fix.jsonl)
All 8 are books-side DUPLICATE_DOCUMENT findings: 4 EXACT_REPEAT (sellers 49 x2, 345, 493) and 4 SAME_NUMBER_DIFFERENT_CONTENT (sellers 161, 198, 346, 494). Each is one accounting document number that appears twice in the seller's own accounting export, on an order whose is-business-order is FALSE. The scenarios are duplicate_same_content and duplicate_different_content; the sim marks these injected defects "optional" (unscored) because the order is non-business.
Assessment (mine, not a ruling): these are a fact about the seller's books file (a number twice in one export), not a judgment that Amazon requires a seller invoice, so the is-business-order rule does not apply to them in the same way. They are true observations in this synthetic data, not wrong results. Whether a books-internal duplicate on a non-business order should still be a confident finding or an informational note is a product decision. Nothing changed for them.
